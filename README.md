# GFS KL website (E2E Draft 1)

One website with three pages and a shared navigation bar:

| Page | Address | What it shows |
| --- | --- | --- |
| Landing | `/` | Scroll-driven film: monthly close, performance and forecast, annual planning, continuous operations. |
| Roadmap | `/roadmap/` | Four finance cycles as a road with buildings, an animated car and activity details per workday. |
| Tower Overview | `/tower-overview/` | Animated anatomy, an interactive 3D organ for each of the eight GFS process towers, and every documented process and activity flow. |

## What to download before hosting

You only need one thing:

1. **Node.js 22.13 or newer.** Go to https://nodejs.org, choose the **LTS** download for your system (Windows installer `.msi`, or macOS `.pkg`), run it, and accept the defaults. It installs `node` and `npm` together.
2. Restart any terminal that was already open, then confirm it worked:

   ```bash
   node --version
   ```

   You should see something like `v22.x.x` or `v24.x.x`.

Nothing else is required to view the site. The ready-built website is already in the `dist/` folder, and the local server uses only Node's built-in modules, so **no `npm install` and no internet connection** are needed just to host it.

You need a current browser with WebGL enabled for the 3D anatomy: Chrome, Edge or Safari.

## Host it locally

1. Open a terminal in this folder (the one containing `package.json`).
   - Windows: open the folder in File Explorer, right-click an empty area, choose **Open in Terminal**.
   - macOS: open Terminal, type `cd `, drag the folder into the window, press Return.
2. Start the server:

   ```bash
   npm start
   ```

3. Wait for this line:

   ```text
   GFS KL website is running at http://127.0.0.1:3000
   ```

4. Open http://127.0.0.1:3000 in your browser.
5. Keep the terminal open while you use the site. Press **Control+C** in the terminal to stop.

Other people on the same network cannot reach it: the server listens only on this computer.

### Troubleshooting

- **`node` or `npm` is not recognised:** Node.js is not installed, or the terminal was open before you installed it. Install it, then open a new terminal.
- **`Could not read package.json`:** the terminal is in the wrong folder. Repeat step 1.
- **`Port 3000 is busy`:** another program is using the port. Stop it, or start on a different port and open that address (for example http://127.0.0.1:3100) instead. Windows PowerShell:

  ```bash
  $env:PORT=3100; npm start
  ```

  macOS or Linux:

  ```bash
  PORT=3100 npm start
  ```
- **`Missing dist/`:** the built site is absent. Follow "Editing and rebuilding" below to recreate it.
- **The page is blank when opened by double-clicking `dist/index.html`:** that is expected. The 3D models, videos and JSON content need the local server, so always use `npm start`.
- **Animations look like they jump instead of glide:** the site respects your system's reduced-motion setting and plays gentler motion. On Windows, turn on Settings > Accessibility > Visual effects > Animation effects to see the full version.

## Folder guide

```
e2e-draft1/
├── dist/                 Ready-to-serve website (generated by npm run build; this is what npm start serves)
├── src/                  Source code, one folder per page
│   ├── shared/           Navigation bar, design layer (theme.css), trackpad-style scrolling, base styles
│   ├── landing/          Landing page (plain HTML/JS: index.html, page.js, scrub-engine.js, styles.css)
│   ├── roadmap/          Roadmap page (React: roadmap.tsx, roadmap.css, dialog, roadmap-cycles.json)
│   └── tower-overview/   Tower overview page (React + Three.js: anatomy scene, process flows, styles)
├── content/              Data loaded by the pages at runtime
│   ├── roadmaps/         One JSON file per finance cycle (close, performance, planning, continuous)
│   ├── towers/           One JSON file per tower/organ (brain = FP&A Commercial, lungs = R2R, ...)
│   ├── anatomy/          3D anatomy atlas and compressed mesh data
│   └── source-markdown/  Raw "Tower Subprocess" extracts the tower and roadmap content was curated from
├── assets/               Brand logo, favicon and the landing-page videos and stills
├── licenses/             Attribution and licence files that must ship with the site
├── docs/                 Landing-page production notes (creative brief, prompts, QA)
├── scripts/              build.mjs (builds dist/), serve.mjs (local server), validate-towers.mjs
├── package.json          npm scripts and pinned dependency versions
└── tsconfig.json         TypeScript settings for the React pages
```

Tower to organ mapping: Brain = FP&A Commercial, Lungs = R2R, Liver = CAPEX, Stomach = P2P, Kidneys = Controlling, Pancreas = FP&A Operations, Spleen = Tax, Intestines = O2C.

## Editing and rebuilding

Only needed if you change anything in `src/`, `content/` or `assets/`. This step needs an internet connection once, to download the build tools into `node_modules/`.

```bash
npm install
npm run build
npm start
```

- `npm run build` recreates `dist/` from `src/`, `content/`, `assets/` and `licenses/`. Edit the sources, never the files in `dist/`.
- `npm run validate` checks every tower JSON file against the shape the tower overview renders.
- Data paths inside the built site: `/data/roadmaps/`, `/data/towers/`, `/data/anatomy/`, `/assets/`.
- Changes do not rebuild automatically: run `npm run build` again and refresh the browser.

## Moving it to another computer

Copy the whole `e2e-draft1` folder (you can leave out `node_modules/`, which is only needed for rebuilding). On the other computer, install Node.js as described above and run `npm start`.

## Hosting elsewhere

`dist/` is a plain static site. Copy that folder to any static web host (or any server that serves files with correct MIME types and supports HTTP range requests for the videos) and the site works without Node.js.
